## 2 快速部署与验证（约一小时）

目标：部署后端与 Web → 打并装模拟版 APK → 走完李四算例（v7 第 6 章）。

### 2.1 部署后端与 Web

约 10 分钟，首次构建要下载依赖。

```
cp deploy/.env.example deploy/.env
```

打开 `deploy/.env`，**至少**改两处：`EGG_DB_PASSWORD`、`EGG_DB_ROOT_PASSWORD`（不要含空格、引号、`#`、`$`）。端口默认 `EGG_WEB_PORT=80`，被占用时改成别的。其余保持默认：默认就是模拟模式（带演示数据，好生意用模拟实现）。然后：

```
docker compose -f deploy/compose.yml up -d --build
docker compose -f deploy/compose.yml ps
curl http://localhost:<端口>/api/health
```

预期：三个服务（mysql、backend、web）都是运行状态，`mysql` 与 `backend` 显示 healthy；`/api/health` 返回 `{"status":"UP","db":"UP"}`。浏览器打开 `http://<服务器地址>:<端口>`，用演示账号登录：

| 角色 | 姓名 | 手机号 | 密码 |
|---|---|---|---|
| 管理员（只能用 Web） | 王会计 | 13900002222 | admin-demo-1234 |
| 磅秤员（只能用 APP） | 张师傅 | 13900001111 | scale-demo-1234 |

登录后左侧导航是：日常（采购入库单、每日基准价）、配置（定价规则、规格与皮重）、系统（好生意档案、磅秤员账号、系统设置、高级选项）。左下角显示当前账套名（模拟模式下是演示账套）。

出问题先看：

```
docker compose -f deploy/compose.yml logs backend --tail 50
```

- 提示缺 `EGG_DB_PASSWORD` 或 `EGG_DB_ROOT_PASSWORD`：`.env` 里没填，照提示补上。
- 数据库密码**只在第一次建库时生效**。库建好后再改 `.env` 里的数据库密码，后端会连不上；要么进库里改，要么 `docker compose -f deploy/compose.yml down -v` 删掉数据卷重建（会丢数据）。
- 第一次构建需要容器能访问外网（下载 Maven 与 npm 依赖）。机器要经代理上网时，构建命令换成：

  ```
  docker build --network host --build-arg HTTPS_PROXY=<代理地址> --build-arg HTTP_PROXY=<代理地址> -f deploy/web.Dockerfile -t egg-web web
  ```

  后端镜像里的 Maven 不读 `HTTPS_PROXY`，还要把 `-Dhttps.proxyHost=… -Dhttps.proxyPort=…` 经 `JAVA_TOOL_OPTIONS` 传进构建阶段；代理会替换 TLS 证书时，再把代理的根证书导入构建阶段 JDK 的信任库。能直接上网的机器不需要这些。

### 2.2 打 APP 并装到手机

```
export ANDROID_HOME=<Android SDK 目录>
cd android
./gradlew :app:assembleSimDebug :app:assembleRealDebug
```

（或在 `android/` 下新建 `local.properties`，写一行 `sdk.dir=<Android SDK 目录>`；该文件不入库。）首次要下载 Gradle 与依赖，之后很快。产物：

| 版本 | 文件 | 包名 | 桌面图标 |
|---|---|---|---|
| 模拟版 | `android/app/build/outputs/apk/sim/debug/app-sim-debug.apk` | `com.jidan.receiving.sim` | 收蛋（模拟版） |
| 实机版 | `android/app/build/outputs/apk/real/debug/app-real-debug.apk` | `com.jidan.receiving` | 收蛋 |

两个包名不同，可以同时装在一台手机上。这是 debug 包，签名用本机的 debug 密钥（`~/.android/debug.keystore`）：要让手机上的旧版“覆盖安装”新版，两次必须用同一台机器、同一把密钥打包，否则要先卸载再装。要换成正式签名，按安卓通常的做法在 `android/app/build.gradle.kts` 里加 `signingConfigs`，本项目没有预置。

**装到手机，两种办法：**

办法一，USB 线：手机开 USB 调试，连电脑。【需手机】

```
adb devices
adb install -r android/app/build/outputs/apk/sim/debug/app-sim-debug.apk
```

`adb` 在 `<Android SDK 目录>/platform-tools/` 里。没连手机时 `adb devices` 列表为空，`adb install` 报 `no devices/emulators found`。

办法二，经站点下载（顺便验证“新版本入口”）：

```
deploy/publish-apk.sh android/app/build/outputs/apk/sim/debug/app-sim-debug.apk
curl http://localhost:<端口>/api/app/version
```

预期：脚本输出 `已发布：app-sim-debug.apk（versionCode 1，versionName 0.1.0）`；`/api/app/version` 返回 `versionCode`、`versionName` 与 `downloadUrl`。读版本号要用 `aapt2`（在 `<Android SDK 目录>/build-tools/<版本>/` 里，设了 `ANDROID_HOME` 就会自己找）；没有时手填：`deploy/publish-apk.sh xxx.apk 1 0.1.0`。手机浏览器打开 `http://<服务器地址>:<端口>/apk/app-sim-debug.apk` 下载并安装（手机要允许“安装未知来源应用”，且手机能访问这个地址）。【需手机】

> 站点只有一个更新入口，指向最近一次发布的 APK。模拟版与实机版包名不同、互不升级，一个站点上通常只发其中一个：试用发模拟版，正式用发实机版。
>
> 要让已装的 APP 出现“有新版本”入口：改 `android/app/build.gradle.kts` 里的 `versionCode`（整数，加 1）与 `versionName`，重新打包，再 `deploy/publish-apk.sh` 发布；APP 在登录页与建单页查一次，发现比本机新就显示下载入口。【需手机】

### 2.3 在手机上完成李四算例验证【需手机】

手机与服务器要在同一局域网（或服务器地址手机能访问）。APP 允许明文 HTTP。

1. 打开“收蛋（模拟版）”。服务器栏填 `http://<服务器地址>:<端口>`（端口是 80 时可省略端口），手机号 `13900001111`，密码 `scale-demo-1234`，登录。输错密码会清空密码；用管理员账号登录会提示只能用 Web。
2. 建单页：尾号输入 `1234`，列出李四与王秀英，选李四；商品“粉蛋”、规格“360枚/箱”自动带出；选收购仓库；主按钮变成“开始收蛋”。
3. 称重页：皮重选“2号包装箱”（2kg）。建单页与称重页底部的**模拟台**用来代替真秤：
   - “放一箱”：按李四 10 箱的顺序依次给重量 `46.5, 45.8, 46, 46, 46, 45.6, 45.6, 45.6, 45.6, 47.8`；每放一箱，称重框稳定后自动记录并变绿，随即“打印”（模拟打印机，模拟台下方有标签预览）。
   - 记完一箱必须先点“拿走”，再“放一箱”，否则不会记第二次。
   - 其他：“一次放 3 箱”“放一只空箱”“断开秤 / 恢复秤”“电量低”；打印机的“缺纸”“开盖”“恢复”；“异常模拟”里的三个开关“读数未扣皮”“稳定标志失灵”“去皮指令无效”。
4. 10 箱称完：已称 `10` 箱、累计 `460.5kg`、均重 `46kg`（小字原始值 `46.05`）；标签预览只有净重、批次、批次序号、二维码，没有均重。
5. 点“确认计量完毕”：汇总页显示均重 `46kg`、收购价格 `181` 元/箱、金额 `1810` 元。
6. 点“提交单据”，完成页显示已提交。
7. 用电脑浏览器以王会计登录 Web：左侧“采购入库单”有待审核，点开这一张；点“审核并回传”，确认框写“审核并回传好生意？”、金额 `1,810 元`、`李四 · 粉蛋 360枚/箱 · 10 箱 × 181 元`、回传的账套名；确认后状态变“已回传”，“好生意单据”显示模拟的单据 ID（形如 `FAKE-1`）。
8. 对照备注（v7 6.3）：到数据库里看回传的报文原文：

```
docker compose -f deploy/compose.yml exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot --default-character-set=utf8mb4 "$MYSQL_DATABASE" -e "select code,status,hs_id,price,amount,push_payload from purchase_order order by id desc limit 1\G"'
```

预期 `price` 为 `181.00`、`amount` 为 `1810.00`，报文里 `comments` 是 `共10箱；逐箱：46.5,45.8,46,46,46,45.6,45.6,45.6,45.6,47.8；归类：45.6kg-4箱,46kg-3箱,46.5kg-1箱,45.8kg-1箱,47.8kg-1箱`，`detailList` 里是 `10 箱 × 181 = 1810`。

### 2.4 没有手机时：用接口完成李四算例验证

下面这段脚本用接口完成“磅秤员提交 → 管理员审核回传”，验证部署出来的后端算得对。存成 `lisi.sh`，需要 `curl` 与 `jq`：

```
#!/usr/bin/env bash
# 用接口走李四算例（v7 第 6 章）：磅秤员提交，管理员审核回传。
set -euo pipefail
B=${1:?用法：lisi.sh http://服务器地址:端口}/api
J='Content-Type: application/json'
login() { curl -fsS "$B/auth/login" -H "$J" -d "{\"phone\":\"$1\",\"password\":\"$2\",\"client\":\"$3\"}" | jq -r .token; }
SCALE=$(login 13900001111 scale-demo-1234 APP)
ADMIN=$(login 13900002222 admin-demo-1234 WEB)

### 5.2 数据线与适配点

数据从秤到好生意的一条线。标 `适配点` 的几处就是适配入口，每处只在一个文件里（spec 11.5）：

```

### 5.3 好生意的联调【需真实账套】

适配文件（`backend/src/main/java/com/egg/chanjet/`）：`RealChanjetClient.java`（鉴权、取 token、四类档案、新增采购入库单）、`StockInPayload.java`（报文字段映射）。文件头逐条写明每个接口依据的开放平台文档，以及文档没说清、按宽松处理的地方。

先弄清几件事（文件头也写了）：

- 接口地址、请求参数与响应字段照畅捷通开放平台文档实现（好业财|好生意 API，文档路径在 `zplus` 下，两个产品共用 `/accounting/openapi/cc/...` 接口）：商品 `product/list/{bookid}`、供应商与客户 `party/custvendor/query/{bookid}`（按往来单位性质 `partyRoleTypeId` 区分，“客户/供应商”两边都算）、仓库 `warehouse/list/{bookid}`、新增采购入库单 `purchasestockin/add/{bookid}`。各接口依据的文档、字段取哪一个，都在 `RealChanjetClient.java` 文件头。
- 文档没说清、代码里按宽松处理的几处：档案接口答复里 `success` 有布尔也有字符串、`code` 有时没有；翻页优先看 `data.totalPage`；token 失效时开放平台答复什么，文档没有列，代码把 HTTP 401 和信息里带“token”字样的失败答复当作失效。真实账套上看到别的样子，只改 `RealChanjetClient.java` 里对应的方法。
- `openToken` 的取法是一个选项 `CHANJET_TOKEN_MODE`（选错了回传不了）：
  - `auto`（默认）：填了 `CHANJET_CERTIFICATE` 就按 `certificate`，否则按 `static`。
  - `certificate`：开放平台“自建应用接入指南”的做法。后端用软证书调“自建应用获取token”（`POST /v1/common/auth/selfBuiltApp/generateToken`）换 `openToken`，存在内存里（有效期约 6 天），快到期前 1 小时自动重新换；业务接口答复 token 失效时重新换一次、把那次请求重发一次。重启后重新换，不落库。
  - `static`：直接用 `CHANJET_OPEN_TOKEN`，不刷新，过期后换新值重启。
- 开放平台里自建应用的“Token 安全级别”：**推荐设为“中”**（软证书 + 请求来源 IP 白名单，把部署服务器的公网出口 IP 加进白名单；不在白名单时换 token 会失败，界面上写明开放平台给的原因）。“低”只要软证书，也能用。“高”还要 `appTicket`，它由开放平台每 10 分钟推送到应用的公网消息接收地址，本系统没有做这个回调，**不支持**。

**切到真实模式：** 编辑 `deploy/.env`：

```
CHANJET_MODE=real
CHANJET_APP_KEY=<你的 appKey>
CHANJET_APP_SECRET=<你的 appSecret>
CHANJET_BOOK_ID=<账套 ID>
CHANJET_CERTIFICATE=<应用管理员授权得到的软证书>
```

没有软证书、手里只有一个现成的 `openToken` 时，把最后一行换成 `CHANJET_OPEN_TOKEN=<openToken>`（`auto` 会自动按静态 token 用）。

然后重建后端：

```
docker compose -f deploy/compose.yml up -d
```

Web“系统 → 高级选项”页不再显示“演示模式”，侧栏左下角的账套名变成“账套 <账套 ID>”（没填密钥时是“未配置账套”）。密钥没填全时服务照常启动：

- 点“好生意档案”的同步：提示“同步失败，保留了上次的数据：还没有配置好生意的连接信息，缺少 CHANJET_APP_KEY、…。在后端的环境变量里填好后重启服务，再重试；这一次没有向好生意发出任何请求”，其中只列实际缺少的几项。
- 审核回传：单据停在“已审核”，回传失败原因同上，可放心重新回传（属于“明确没发出去”）。

**每次调用的原始请求与响应都在后端日志里**（appKey、appSecret、openToken、软证书只显示前后各两位；换 token 的答复只记有效期），排查时看：

```

**补充说明**

- **读数是否已扣皮**：改完选项后，在手机上新建一单（每次开始称重会取最新选项），再放一箱已知重量核对称重框净重。只在 `core/NetWeight.kt` 处理这一件事；三种组合的换算见文件头。合并称重时秤只扣一份皮，其余 k−1 份由 `NetWeight` 补扣。
- **去皮方法**：`LanstarScale.kt` 有三个去皮方法（设数字皮、称重去皮、清皮）。`scale.tare-by = scale` 时“称空箱”调其中的称重去皮，`app` 时只在 APP 侧记下；称重皮与数字皮互斥，切换前先清皮，适配器内部已处理；总时限 8 秒。
- **“称空箱”按钮**：等读数稳定后才亮，写明按多少 kg 去皮（写的是秤上现在的读数）；空秤、整箱蛋或读数未稳时灰着。称重皮的皮重名记“空箱”。新开一单时皮重卡片总是展开、称重框锁定，上一单用的包装箱排在首位并标“上一单用的”，不会自动选中。
- **兜底的记录方式**：`weigh.record-by = button` 时称重框出现“记录”按钮，按了才记，此时只要求秤能把重量数字传上来。再不行用流水里的“手工加一箱”（`weigh.manual-entry` 不要关）。
- **断线重连**：SDK 的自动连接没有打开，自动重连只由 `LinkKeeper` 做，掉线（SDK 连接码 31）报“丢失”。
- 选项改在 Web 高级选项页的“设备与接口适配”组；记录方式、箱数识别、手工录入在“作业策略”组。换算与状态机的改动都有单测：改完跑 `cd android && ./gradlew :core:test :device:test`。

### 5.6 打印机的联调【需真设备】

适配文件：`android/device/src/main/kotlin/com/jidan/receiving/device/gainscha/`：`GainschaPrinter.kt`（编码、两种产物拼装、状态轮询）、`GainschaCodes.kt`（结果码与状态码映射表）、`SdkGainschaSdk.kt`（SDK 调用，唯一出现厂商类的地方）；标签版式在 `device/label/LabelTemplate.kt`。依据：`sdk/` 里的 TSPL 编程手册 v1.0.8、佳博 SDK2 2.0.3 API 说明文档与 aar。

**联调步骤**

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 蓝牙连接方式（经典蓝牙/BLE，`T-01`） | 设备弹层点“搜索打印机”，选 GP-M32B 连接，点“打一张测试标签” | 搜得到、连得上；出一张带中文一行“收蛋 测试 0123456789”的标签；关机或走远后显示丢失，回来自动重连 |
| 2 正常打印中文 | 逐箱记一箱，看标签 | 汉字不乱码；要素：净重、批次、批次序号、二维码（`label.content = full` 时共 9 项）；都不印均重 |
| 3 版式与偏移 | 看标签位置、大小 | 内容在标签纸内、不被裁切 |
| 4 二维码 | 手机扫标签；文字版与位图版各扫一次 | 内容为 `批次号#批次序号`（例如 `SG20261116-10#3`）；用箱码查询接口能查到 |
| 5 缺纸、开盖 | 抽掉纸，打一张；开盖，再打一张；各自恢复 | 状态标签变化；打印队列停在当前一张，未打出的保持“未打印”；恢复后一键补打成功 |
| 6 一票一控 | 打印一张后看有无多余出纸或乱码 | 无副作用 |
| 7 TSPL 语法 | 看 logcat | 每张标签发送前，指令文本打在标签 `GainschaPrinter` 下，对照 `sdk/标签打印机TSPL编程手册  v1.0.8.pdf` 检查 |

**不符合时**

| 现象 | 先调哪个配置项 | 改哪个文件 |
|---|---|---|
| 连不上 | 没有选项可换；打印可整体关：`print.enabled = off`，不影响收蛋与提交 | 见下“蓝牙连接方式” |
| 汉字乱码、缺字 | `print.render = bitmap`（整张图片，绕开字库与编码） | `LabelRenderer.toTspl`（文字版的 TEXT 指令与 GB18030 编码） |
| 文字版净重行偏小 | `print.render = bitmap` | `LabelRenderer.toTspl`（见下“文字版字高”） |
| 标签纸尺寸不对 | Web“系统设置”里的宽、高、间隙 | — |
| 内容整体偏位 | `print.offset-x-mm`、`print.offset-y-mm`（毫米，向右、向下为正，文字与二维码一起移；文字版与位图版都生效） | — |
| 换了 300 DPI 机型 | `print.dpi = 300`（每毫米 12 点；默认 `203`，每毫米 8 点，v7 7.3） | — |
| 版式仍不合适 | — | `LabelTemplate.kt` 里各要素的 mm 坐标（一处） |
| 缺纸、开盖的状态对不上 | 暂时不想让界面提示：`print.enabled = off` | `GainschaCodes.kt` 的 `issueOf`（见下“状态位映射”） |
| 一票一控有副作用 | — | `GainschaCodes.NO_REPLY_IS_SUCCESS` 与 `SdkGainschaSdk.printTracked` |
| TSPL 指令对不上手册 | — | `LabelRenderer.toTspl` |

**补充说明**

- **蓝牙连接方式（`T-01`）**：SDK 的 `ConnectType.BLUETOOTH` 是经典蓝牙，v7 7.3 记录 GP-M32B 在 v1 里被称为 BLE，**以真机为准**。连不上时的做法（spec 附录 C 第 20 条，开发方不预先实现）：保留 `LabelRenderer` 的 TSPL 拼装与 `GainschaPrinter` 的编码，另写一个实现 `GainschaSdk` 接口（6 个成员：断开回调、搜索、连接、断开、发送并取状态、询问）的类，用安卓原生 BLE（`BluetoothGatt` 写特征值）发送同样的字节，再把 `app/src/real/.../registry/DeviceRegistry.kt` 里的 `SdkGainschaSdk(context)` 换成它。SDK 自己重连（`setAutoReConnect(true, 3)`）与 `LinkKeeper` 同时在重连，要留意双端自动重连是否冲突。
- **文字版字高**：文字版 TEXT 指令用 `TSS24.BF2` 字库、字符串转 GB18030 发出（`TsplBytes.encode`）。该字库字高固定 24 点（约 3mm），模板里 `LabelField.fontMm` 只在位图版生效，净重行（5mm）在文字版会偏小：要让文字版更大，改 TSPL 的 `TEXT` 放大倍数参数（`LabelRenderer.toTspl`）。
- **版式与偏移**：毫米换点数与偏移集中在 `LabelRenderer.layout` 与 `LabelGeometry`，TSPL 与位图共用它。改完下一次建单生效（4.4）；偏移量与分辨率换算只有单测，没在真标签上量过。
- **二维码**：文字版用 TSPL `QRCODE`，位图版用 zxing，纠错等级都是 L。
- **状态位映射**：`issueOf` 把 `<ESC>!?` 回复字节按位映射（0 开盖、1 卡纸、2 缺纸、3 无碳带、4 暂停、5 正在打印、6 外盖打开、7 过热），一票一控状态码 `0x20`–`0x26` 映射成功或失败原因。对着真机把哪些位置起了记下来再改映射；第 7 位 SDK 称“其他错误”，本项目按“过热”。
- **一票一控**：SDK 的 `printWithOrderTracking` 会在 TSPL 数据前后各发一帧 `1D 0B 01 …`（ESC/POS 系的订单起止标记）。有副作用就把 `GainschaCodes.NO_REPLY_IS_SUCCESS` 与 `SdkGainschaSdk.printTracked` 改成只发数据。该常量为 `true`：这台机型没有答复时按成功算，所以“已送出”不等于“已打出”，实测时留意。
- **TSPL 语法**：`LabelRenderer.toTspl` 里每条指令以 CR LF 结尾、公制单位与数字之间有空格、`GAP` 两个参数都带 `mm`。已对照 SIZE、GAP、DIRECTION、CLS、TEXT、QRCODE、BITMAP、PRINT 并用单测固化指令文本。

## 6 全链路验收

【需手机】【需真设备】【需真实账套】前提：秤、打印机、好生意的联调步骤（5.3 至 5.6）已通过，账套里有供应商“李四”（手机号 `13603511234`，或你自己定的等价农户）、商品“粉蛋”、仓库。**照 v7 第 6 章逐条做，期望值以 v7 为准**，下面只列要点；结果记到看板全链路行（`H-4`）的备注里。

- **数据准备**（v7 6.1，Web 里配）：规格 `360枚/箱`、标准净含量 `45kg`；包装箱 `2号包装箱 = 2kg`；当日 `360枚/箱` 基准价 `180`；定价规则“粉蛋李四收购定价方案”（粉蛋、`360枚/箱`、换算系数 `1`）绑定李四；系统设置保持默认（四舍五入、逐箱打印、精简标签）。
- **作业**（v7 6.2）：APP 建单（尾号 `1234`、选李四、选仓库）→ 称重页选“2号包装箱”，空秤显示 `-2kg` → 逐箱称重，每记一箱打一张标签 → 10 箱后“确认计量完毕” → 提交 → Web 审核回传。
- **期望值**：真秤上没有现成的 `46.5, 45.8, …` 十箱重量，用砝码或配重凑出一批每箱不同的净重，**按公式算**：均重 = 总净重 ÷ 箱数，按取整规则取到整数 kg（四舍五入）；收购价格 = 180 + 换算系数 × (均重 − 45)；金额 = 箱数 × 收购价格。要原样复现 v7 的数字，就凑出 `46.5, 45.8, 46, 46, 46, 45.6, 45.6, 45.6, 45.6, 47.8`（合计 `460.5kg`、均重 `46kg`、价格 `181`、金额 `1810`）。
- **好生意里核对**（v7 6.3）：供应商李四；仓库为所选仓库；商品行 `粉蛋｜360枚/箱｜10箱｜181元/箱｜1810元`；备注与 2.3 步骤 8 的 `comments` 一致。
- **补充**：取整对照（v7 6.5）改系统设置里的取整规则，保存按钮写明有几张待审核单会重算，抹零 `46kg / 181 / 1810`、进位 `47kg / 182 / 1820`；手工录入（v7 6.6）同 2.3 的补充算例；合并称重（v7 6.7）在真秤上放 3 箱各 46kg（皮 2kg），预期识别 3 箱，合计皮重 `6kg`，净重合计 `138kg`，3 条流水各 `46kg`。
- **异常路径**：回传失败 → 重新回传 / 退回待审核；没收到答复 → 先核对再重传 / 标记为已回传；缺纸停打再补打；秤走出范围后自动重连。做法见 5.3、5.5、5.6。

## 7 上线与维护

### 7.1 正式部署清单

`deploy/.env` 里要改的（`.env.example` 末尾也有这张清单）：

| 项 | 改成 |
|---|---|
| `EGG_DB_PASSWORD`、`EGG_DB_ROOT_PASSWORD` | 自己的密码（只在第一次建库时生效） |
| `EGG_SEED_DEMO` | `false`（演示账号的密码是公开的）。compose 在 `.env` 里没写这项时按 `false` 处理 |
| `EGG_ADMIN_PHONE`、`EGG_ADMIN_PASSWORD`、`EGG_ADMIN_NAME` | 初始管理员，**必填**，否则没人能登录 Web |
| `CHANJET_MODE` 等 | 要连真实好生意时 `real`，填 appKey、appSecret、账套 ID 与软证书（5.3） |
| `EGG_WEB_PORT` | 站点对外端口，默认 80 |

```
docker compose -f deploy/compose.yml up -d --build
```

只有站点对外开放端口，数据库与后端不开放。时区统一 `Asia/Shanghai`，“当日”以服务器日期为准。

站点前面再套一层终止 HTTPS 的代理时：要让它带上原始的 `Host`，并把 `deploy/nginx.conf` 里 `/api/app/version` 一段的 `$scheme` 换成 `https`，否则 APP 拿到的下载链接是 `http://`。

### 7.2 初始管理员

启动时若库里没有任何管理员，用 `EGG_ADMIN_PHONE`、`EGG_ADMIN_PASSWORD`、`EGG_ADMIN_NAME` 建一个；已有管理员时这三项不起作用（改环境变量不会改已有管理员的密码）。姓名含中文时运行后端的环境要用 UTF-8（compose 已设 `LANG=C.UTF-8`）。系统**没有管理员管理与改密码页面**（spec 7.2）。磅秤员账号在 Web“磅秤员账号”页新增、重置密码、停用。

忘记管理员密码：删掉库里的管理员账号，再用环境变量重建：

```
docker compose -f deploy/compose.yml exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot --default-character-set=utf8mb4 "$MYSQL_DATABASE" -e "delete from account where role=\"ADMIN\""'
```

改好 `.env` 里的 `EGG_ADMIN_*`，然后 `docker compose -f deploy/compose.yml up -d`（环境变量变了会重建后端容器），启动日志出现“已创建初始管理员”。

### 7.3 每日备份

```
deploy/backup.sh
```

默认放在 `deploy/backups/`（只让当前用户读），保留 14 天；`EGG_BACKUP_DIR`、`EGG_BACKUP_KEEP_DAYS` 可改。导出用 `mysqldump --single-transaction`，收蛋照常；导出不完整就丢弃，不留一份看着正常的坏备份。

每日定时（服务器上 `crontab -e`，把 `/opt/egg` 换成仓库在服务器上的实际目录；备份目录先要存在：`mkdir -p /opt/egg/deploy/backups`）：

```
30 2 * * * /opt/egg/deploy/backup.sh >> /opt/egg/deploy/backups/backup.log 2>&1
```

**备份只在本机**，要防整机损坏，请自己把备份目录同步到另一台机器或网盘（本项目不做）。装好 crontab 后隔天确认备份文件生成。

恢复（会覆盖现有数据，先停后端；库名、账号与 `.env` 一致）：

```
docker compose -f deploy/compose.yml stop web backend
gunzip -c deploy/backups/egg-XXXXXXXX-XXXXXX.sql.gz | docker compose -f deploy/compose.yml exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot --default-character-set=utf8mb4 "$MYSQL_DATABASE"'
docker compose -f deploy/compose.yml start backend web
```

### 7.4 升级与停止

- 后端与 Web：拉新代码后 `docker compose -f deploy/compose.yml up -d --build`，数据在数据卷里不会丢；改表靠 Flyway 脚本自动追加。升级前先 `deploy/backup.sh`。
- APP：改 `versionCode`/`versionName`，重新打包，`deploy/publish-apk.sh` 发布，不用重启（2.2）。手机上的 APP 在登录页与建单页查到新版本就出现下载入口。接口只增不改，旧版 APP 遇到新后端照常能用。

停止服务：

```
docker compose -f deploy/compose.yml down
```

停掉服务，数据卷保留；再 `up -d` 数据还在。加 `-v`（`down -v`）才会删库，**不可恢复**。

### 7.5 本机开发与调试

开发时只起库，后端与 Web 在本机跑（默认端口 3306、8080、5173；已被占用时用下面的环境变量换端口）：

```
docker compose -f deploy/compose.dev.yml up -d
